# LA 중앙교회 주일 모바일 소식지

휴대폰과 PC에서 보는 3개 언어(한국어·English·Español) 주보 웹페이지입니다.
**모두 무료**로 운영됩니다. Google Apps Script와 GitHub Pages를 씁니다.

```
[구글 드라이브 주보 폴더]  ← 사무실이 매주 PDF/이미지/문서 업로드 (폴더는 비공개여도 됨)
          │  토·일 매시간 자동 확인 (Apps Script)
          ▼
[구글 시트: 주차별 탭]     ← 자동 추출 결과. 틀린 곳만 고치면 됨
          │  JSON 공개 (Apps Script 웹앱)
          ▼
[모바일 소식지 페이지]        ← GitHub Pages. 링크만 있으면 누구나 볼 수 있음
```

## 화면 구성 (중요한 순서)
1. **주일 말씀**: 설교 제목(가장 크게), 성경 본문, 설교자, 찬양 번호와 제목, 예배 순서
2. **이번 주 암송 말씀**: "암송 연습" 버튼을 누르면 단어가 가려지고, 눌러서 확인합니다 (아이들용)
3. 교회 소식 · 일정 · **봉사 안내**(이름 검색 가능) · 기도 제목
4. 원본 주보 보기 (PDF 원본 링크, 전체 글)

- 위쪽의 **한국어 / EN / ES** 버튼으로 언어를 바꿉니다. 고른 언어는 기억됩니다.
- **가 (큰 글씨)** 버튼을 누를 때마다 보통 → 큰 글씨 → 아주 큰 글씨로 바뀝니다.
- 지난 주 주보는 위쪽 화살표(‹ 지난주)로 볼 수 있습니다.
- 휴대폰이 다크 모드면 어두운 화면으로 보입니다. 인터넷이 끊겨도 마지막으로 본 주보가 보입니다.
- 하단의 **QR 코드** 버튼으로 QR을 띄울 수 있습니다. 종이 주보에 인쇄해 두기 좋습니다.
- 링크 예: `.../?lang=en`처럼 보내면 영어로 열립니다.

## 설치 1단계: Apps Script (자동 업데이트 엔진), 약 10분

> **주보 폴더에 접근 권한이 있는 구글 계정**으로 진행하세요 (폴더 주인 계정 권장).

1. https://script.google.com 에서 **새 프로젝트**를 만듭니다. 이름은 예: `중앙교회 모바일주보`
2. 왼쪽 ⚙️ **프로젝트 설정**에서 **"appsscript.json 매니페스트 파일을 편집기에 표시"**를 체크합니다.
3. 편집기의 `Code.gs` 내용을 모두 지우고, 이 저장소의 `apps-script/Code.gs`를 붙여넣습니다.
4. `appsscript.json`도 `apps-script/appsscript.json` 내용으로 바꿉니다. 이렇게 하면 Drive API가 켜집니다.
5. 💾 저장한 뒤, 위쪽 함수 선택에서 **`setup`**을 고르고 **▶ 실행**합니다.
   - "권한 검토"가 나오면 계정을 선택하고 **고급 → (안전하지 않음)으로 이동 → 허용**을 누릅니다. 내 계정이 만든 스크립트라서 나오는 정상 경고입니다.
   - 실행 로그에 **데이터 시트 주소**가 나옵니다. 시트는 주보 폴더 안에 생깁니다.
6. 오른쪽 위 **배포 → 새 배포**로 갑니다.
   - 유형: **웹 앱**
   - 다음 사용자 인증 정보로 실행: **나**
   - 액세스 권한이 있는 사용자: **모든 사용자**
   - **배포**를 누르고, 나오는 **웹 앱 URL**(`https://script.google.com/macros/s/…/exec`)을 복사합니다.
7. 이 URL을 브라우저에 붙여넣어 JSON 글자가 보이면 성공입니다.

`setup`을 실행하면 **매시간 확인 트리거**가 자동으로 설치됩니다. 실제 확인은 **토요일과 주일(LA 시간)에만** 하고, 다른 요일에는 바로 끝납니다.

## 설치 2단계: 웹페이지 무료 배포 (GitHub Pages), 약 10분

1. `config.js`를 열어 `API_URL: ''` 따옴표 안에 1단계의 웹 앱 URL을 붙여넣습니다.
   (주소·전화·홈페이지도 넣으면 하단에 표시됩니다.)
2. https://github.com 에 가입(무료)하고 **New repository**를 만듭니다. 예: `jungang-bulletin`, **Public**
3. **Add file → Upload files**에서 아래 파일을 끌어다 놓고 **Commit**합니다.
   `index.html`, `styles.css`, `app.js`, `config.js`, `sample-data.json`, `manifest.webmanifest`, `icon.svg`, `.nojekyll`
4. 저장소의 **Settings → Pages**에서 Source를 **Deploy from a branch**, Branch를 **main / (root)**로 정하고 **Save**합니다.
5. 1~2분 뒤 `https://<아이디>.github.io/jungang-bulletin/` 주소가 생깁니다. **이 링크를 교우들에게 보내면 됩니다.**

> **저장소를 Private으로 하고 싶다면:** 무료 GitHub 요금제에서는 Pages가 **Public 저장소**에서만 동작합니다. Private 저장소로 하려면 **Cloudflare Pages**(무료)를 GitHub의 Private 저장소에 연결하거나, Netlify Drop에 폴더를 끌어다 놓아 배포하세요.
> 어느 쪽이든 페이지에는 검색엔진 차단(noindex)이 걸려 있어서 **링크를 받은 사람만** 찾아 들어올 수 있습니다.
>
> 다른 무료 호스팅도 됩니다. **Netlify Drop**(https://app.netlify.com/drop)에는 폴더를 끌어다 놓기만 하면 되고, **Cloudflare Pages**도 쓸 수 있습니다.

## 매주 하는 일 (사무실)

1. **토요일까지** 주보 파일 3개를 드라이브 폴더에 올립니다. 파일 이름은 이렇게 권장합니다.
   - `2026-11-15_KO.pdf`, `2026-11-15_EN.pdf`, `2026-11-15_ES.pdf`
   - 날짜와 언어(KO/EN/ES, 한국어/영어/스페니쉬도 인식)가 이름에 있으면 가장 정확합니다.
     이름에 날짜가 없으면 **올린 날 기준 다가오는 주일**로 처리합니다.
   - PDF, 이미지(JPG/PNG), 구글 문서, Word, 구글 슬라이드 모두 됩니다.
2. 1시간 안에 자동으로 반영됩니다. 바로 반영하려면 Apps Script에서 `checkNow`를 실행하세요.
3. **데이터 시트**의 해당 주 탭(예: `2026-11-15`)을 열어 **설교 제목·본문·찬양**을 한 번 확인합니다.
   틀린 칸을 고치면 약 2분 안에 웹에 반영됩니다.
   - 고친 뒤 파일을 다시 올려도 덮어쓰지 않게 하려면 **잠금** 행에 `Y`를 입력하세요.
   - 일정은 `11/15(일) | 추수감사주일`, 봉사는 `안내 | 김OO, 이OO`처럼 `|`로 구분하고, 한 줄에 하나씩 씁니다.
   - PDF 없이 시트에 직접 입력해도 됩니다. 탭 이름은 `YYYY-MM-DD` 형식의 주일 날짜로 하세요.

## 참고
- **LA 중앙교회 주보 양식 자동 인식**: `lacc-parser.js`가 영어 주보와 한국어·스페인어 주보(구글 문서)를 읽고 항목을 나눕니다.
  말씀 주제와 본문, 찬송, 설교자·장소, 예배 시간, 수련회 안내·회비, 교제 일정, 봉사(이번 주/다음 주), 월간 성구암송·안내봉사 담당,
  이번 주 묵상 말씀, 성구암송(이번 주/다음 주), 정기 모임, 주소를 찾아냅니다.
  분석은 웹페이지에서 하므로, 규칙을 고칠 때 Apps Script는 다시 설치하지 않아도 됩니다.
  주보 양식이 크게 바뀌면 `lacc-parser.js`만 고치면 됩니다.
- **11월 8일(2026-11-08) 이후** 주보만 표시됩니다. 바꾸려면 `Code.gs`의 `START_DATE`를 고치세요.
- 원본 보기 버튼을 위해, 처리된 주보 파일은 "링크가 있는 모든 사용자 보기"로 공유됩니다. 폴더 자체는 그대로입니다.
  원하지 않으면 `SHARE_FILES_PUBLICLY: false`로 바꾸세요.
- 자동 추출은 "설교 / 본문 / 찬송 / 암송 / 광고 / 일정 / 봉사 / 기도제목"(영어·스페인어 제목 포함) 같은
  **소제목을 기준**으로 내용을 나눕니다. 주보 양식이 특이하면 처음 몇 주는 시트에서 확인해 주세요.
  `testLatestFile`을 실행하면 가장 최근 파일의 추출 결과를 로그로 볼 수 있습니다.
- `config.js`의 `API_URL`이 비어 있으면 예시 데이터(`sample-data.json`)가 "예시 화면" 표시와 함께 보입니다.
- Code.gs를 고친 뒤에는 **배포 → 배포 관리 → ✏️ → 버전: 새 버전 → 배포**를 해야 반영됩니다. 이렇게 하면 URL은 그대로입니다.
